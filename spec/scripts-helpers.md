# EPAC Helper Scripts

Located in `Scripts/Helpers/` (~128 scripts) and `Scripts/Helpers/RestMethods/` (13 scripts). These are internal functions loaded via `Add-HelperScripts.ps1` (in script mode) or via `internal/functions/` (in module mode). They are not directly invoked by users.

---

## Loading Mechanism

`Add-HelperScripts.ps1` dot-sources every `.ps1` file in the Helpers directory and RestMethods subdirectory, making all helper functions available in the caller's scope.

## Category 1: Build-* (Deployment Plan Builders)

**Scripts (10):**
`Build-AssignmentDefinitionAtLeaf`, `Build-AssignmentDefinitionEntry`, `Build-AssignmentDefinitionNode`, `Build-AssignmentIdentityChanges`, `Build-AssignmentParameterObject`, `Build-AssignmentPlan`, `Build-ExemptionsPlan`, `Build-PolicyPlan`, `Build-PolicySetPlan`, `Build-PolicySetPolicyDefinitionIds`

**Purpose:** Construct deployment plans by comparing desired state (JSON files) against current Azure state. Each returns a hashtable with `.new`, `.update`, `.replace`, `.delete` collections.

### Build-AssignmentPlan
Main orchestrator for policy assignment change planning.
- Loads assignment JSON files from root folder
- Recursively builds the assignment definition tree via `Build-AssignmentDefinitionNode`
- Compares each desired assignment against deployed state using deep equality helpers
- Tracks changes by type: `displayName`, `parameters`, `metadata`, `enforcementMode`, `notScopes`, `nonComplianceMessages`, `overrides`, `resourceSelectors`
- Generates role assignment changes for managed identities via `Build-AssignmentIdentityChanges`
- Determines delete candidates based on `Confirm-PacOwner` and `Confirm-DeleteForStrategy`

### Build-AssignmentDefinitionNode (recursive)
Processes a JSON assignment tree node:
1. Merges parent properties into the current node (cascade)
2. If the node has `children`, recurse into each child
3. If the node has `definitionEntry` or `definitionEntryList`, it is a leaf — call `Build-AssignmentDefinitionAtLeaf`
4. At leaves, validate scopes, merge parameters, and emit final assignment objects

### Build-PolicyPlan
Compares desired custom policy definitions against deployed:
- Classifies each deployed policy by `Confirm-PacOwner`
- Uses `Confirm-PolicyDefinitionsMatch` for change detection
- Tracks `new`, `update`, `replace` (when id/name changes), `delete`

### Build-PolicySetPlan
Same pattern as `Build-PolicyPlan` but for policy sets:
- Additionally calls `Build-PolicySetPolicyDefinitionIds` to resolve policy IDs within the set
- Detects changes to `policyDefinitions` array membership

### Build-ExemptionsPlan
Plans exemption changes:
- Calls `Confirm-ActiveAzExemptions` to classify deployed exemptions (active, expired, orphaned)
- Matches desired exemptions to deployed by ID
- Handles expiration date changes and orphaned exemption cleanup

### Build-AssignmentParameterObject
Constructs the final parameter value object for an assignment, merging parameters from all ancestor nodes with child overrides taking precedence.

### Build-AssignmentIdentityChanges
Computes required role assignment changes when a managed identity type or location changes on an assignment.

## Category 2: Confirm-* (Validation & Comparison)

**Scripts (17):**
`Confirm-ActiveAzExemptions`, `Confirm-DeleteForStrategy`, `Confirm-EffectIsAllowed`, `Confirm-MetadataMatches`, `Confirm-NullOrEmptyValue`, `Confirm-ObjectValueEqualityDeep`, `Confirm-PacOwner`, `Confirm-ParametersDefinitionMatch`, `Confirm-ParametersUsageMatches`, `Confirm-PolicyDefinitionUsedExists`, `Confirm-PolicyDefinitionsInPolicySetMatch`, `Confirm-PolicyDefinitionsMatch`, `Confirm-PolicyDefinitionsParametersMatch`, `Confirm-PolicyResourceExclusions`, `Confirm-PolicySetDefinitionUsedExists`, `Confirm-ValidPolicyResourceName`, `Compare-HydrationMetadata`

**Purpose:** Boolean or classified return values that enable Build-* scripts to make intelligent deployment decisions.

### Confirm-PacOwner
Determines the ownership class of a deployed resource:
- `thisPaC` — `metadata.pacOwnerId` matches this instance's `pacOwnerId`
- `otherPaC` — `metadata.pacOwnerId` exists but is a different GUID
- `unknownOwner` — no `metadata.pacOwnerId` present
- `managedByDfcSecurityPolicies` — description contains "This object has been generated by..."
- `managedByDfcDefenderPlans` — description contains "This policy assignment was automatically created by..."

### Confirm-DeleteForStrategy
Returns `$true` if a resource should be deleted given its ownership and the deployment strategy:

| Owner | `full` strategy | `ownedOnly` strategy |
|-------|----------------|----------------------|
| `thisPaC` | ✓ delete | ✓ delete |
| `otherPaC` | ✗ keep | ✗ keep |
| `unknownOwner` | ✓ delete | ✗ keep |
| `managedByDfcSecurityPolicies` | configurable | ✗ keep |
| `managedByDfcDefenderPlans` | configurable | ✗ keep |

### Confirm-MetadataMatches
Deep-compares metadata objects after filtering out system-managed properties (`createdBy`, `createdOn`, `updatedBy`, `updatedOn`, `lastSyncedToArgOn`). Returns a tuple `($match, $changePacOwnerId)`.

### Confirm-ObjectValueEqualityDeep
Recursive deep-equality check for any two PowerShell objects (hashtable, PSCustomObject, array, scalar). Used extensively in change detection.

### Confirm-ParametersUsageMatches
Compares parameter values between desired and deployed assignments, handling `$Current` placeholder resolution and effect parameter overrides.

### Confirm-PolicyDefinitionsMatch
Compares two policy definition objects for semantic equivalence, ignoring system-generated fields.

### Confirm-EffectIsAllowed
Validates that a requested effect value is in the `allowedValues` list of the effect parameter definition.

### Confirm-NullOrEmptyValue
Returns `$true` if a value is null, empty string, empty array, or empty hashtable.

### Confirm-PolicyResourceExclusions
Checks if a policy resource ID appears in the `excludedPolicyDefinitions`, `excludedPolicySetDefinitions`, or `excludedPolicyAssignments` lists.

## Category 3: Get-* (Data Retrieval)

**Scripts (24):**
`Get-AzPolicyAssignments`, `Get-AzPolicyExemptions`, `Get-AzPolicyOrSetDefinitions`, `Get-AzPolicyResources`, `Get-AzPolicyResourcesDetails`, `Get-CalculatedPolicyAssignmentsAndReferenceIds`, `Get-CustomMetadata`, `Get-DeepCloneAsOrderedHashtable`, `Get-DefinitionsFullPath`, `Get-DeploymentPlan`, `Get-GlobalSettings`, `Get-HydrationChildManagementGroupNameList`, `Get-HydrationDefinitionSubfolderByContentId`, `Get-HydrationEpacRepo`, `Get-HydrationMessageBlock`, `Get-HydrationQuestionList`, `Get-HydrationUserObjectId`, `Get-PacFolders`, `Get-ParameterNameFromValueString`, `Get-PolicyAssignmentsDetails`, `Get-PolicyEffectDetails`, `Get-PolicyResourceProperties`, `Get-ScrubbedString`, `Get-SelectorArrays`

### Get-AzPolicyResources
The central Azure query function. Orchestrates:
1. `Get-AzPolicyOrSetDefinitions` — retrieves all policy and policy set definitions
2. `Get-AzPolicyAssignments` — retrieves assignments with ownership classification
3. `Get-AzPolicyExemptions` — retrieves exemptions with expiration tracking
4. Role assignment retrieval via REST

Returns a massive nested hashtable:
```
{
  policyDefinitions: { all: {}, readOnly: {}, managed: {}, ... }
  policySetDefinitions: { all: {}, readOnly: {}, managed: {}, ... }
  policyAssignments: { all: {}, managed: {}, thisPaC: {}, otherPaC: {}, dfc: {} }
  policyExemptions: { all: {}, managed: {}, orphaned: {}, expired: {} }
  roleAssignments: { byPrincipalId: {} }
  roleDefinitions: {}
  counters: { policyDefinitions: {...}, policySetDefinitions: {...}, assignments: {...} }
}
```

### Get-GlobalSettings
Reads and parses `global-settings.jsonc`. Validates required fields, resolves relative paths for definitions folder, and returns the parsed settings object.

### Get-PacFolders
Resolves the five standard subfolder paths from the definitions root:
- `policyDefinitionsFolder`
- `policySetDefinitionsFolder`
- `policyAssignmentsFolder`
- `policyExemptionsFolder`
- `policyDocumentationsFolder`

### Get-DeploymentPlan
Reads a JSON plan file from disk, validates JSON syntax, and returns a hashtable. Called by `Deploy-PolicyPlan.ps1` and `Deploy-RolesPlan.ps1`.

### Get-PolicyResourceProperties
Normalizes property access across different Azure resource types, handling type conversions between PSCustomObject and hashtable.

### Get-DeepCloneAsOrderedHashtable
Deep-clones any object into an `OrderedDictionary` (preserving key order), handling PSCustomObject, Hashtable, and arrays recursively.

### Get-DefinitionsFullPath
Resolves relative paths within definition files to full absolute paths.

## Category 4: Convert-* / ConvertTo-* (Data Transformation)

**Scripts (17):**
`Convert-AllowedEffectsToCsvString`, `Convert-EffectToCsvString`, `Convert-EffectToMarkdownString`, `Convert-EffectToOrdinal`, `Convert-HashtableToFlatPsObject`, `Convert-ObjectToComparableJson`, `Convert-OrdinalToEffectDisplayName`, `Convert-ParametersToString`, `Convert-PolicyResourcesDetailsToFlatList`, `Convert-PolicyResourcesDetailsToFlatList-Documentation`, `Convert-PolicyResourcesToDetails`, `Convert-PolicySetToDetails`, `Convert-PolicyToDetails`, `ConvertTo-ArrayList`, `ConvertTo-DisplayString`, `ConvertTo-HashTable`, `Compare-SemanticVersion`

### Convert-PolicyToDetails
Analyzes a policy definition object and extracts structured details:
- `displayName`, `description`, `category` (from metadata)
- `effectValue`, `effectDefault`, `effectAllowedValues`, `effectAllowedOverrides`
- `parameters` map with defaults, allowed values, and constraint metadata
- Deprecation and version information from metadata

### Convert-PolicySetToDetails
Same as above for policy sets, additionally building a parameter-to-policy mapping.

### Convert-PolicyResourcesToDetails
Converts the raw `Get-AzPolicyResources` output into a searchable flat details dictionary used by `Build-AssignmentPlan` and documentation scripts.

### ConvertTo-HashTable
Universal converter from PSCustomObject or IDictionary to `OrderedHashtable`, preserving key order. Widely used after JSON deserialization.

### Convert-ObjectToComparableJson
Serializes an object to sorted-key JSON for deterministic comparison.

### Convert-EffectToOrdinal / Convert-OrdinalToEffectDisplayName
Map effect strings to ordinal integers and back for sorting and display:
```
Disabled=0, Audit=1, AuditIfNotExists=2, Append=3, Modify=4,
DeployIfNotExists=5, Deny=6, Manual=7, DenyAction=8
```

### Compare-SemanticVersion
Compares two semantic version strings (e.g., `1.2.3`) and returns -1, 0, or 1.

## Category 5: Scope Table Builders

**Scripts (3):**
`Build-ScopeTableForDeploymentRootScope`, `Build-ScopeTableForManagementGroup`, `Build-ScopeTableForSubscription`

### Purpose
Build a flat lookup table of all in-scope management groups and subscriptions under the `deploymentRootScope`, respecting exclusion rules.

### Build-ScopeTableForDeploymentRootScope
Entry point. Determines if the root is a management group or subscription, then delegates to the appropriate builder.

### Build-ScopeTableForManagementGroup
Recursively walks the management group hierarchy via `Get-AzManagementGroupRestMethod`, applying `excludedScopes` (wildcard-supported) and `excludeSubscriptions` filters. Returns a hashtable keyed by scope ID.

### Build-ScopeTableForSubscription
Builds a single-entry scope table for subscription-rooted deployments.

## RestMethods/ — Azure REST API Wrappers

Located in `Scripts/Helpers/RestMethods/`. 13 thin wrapper functions over `Invoke-AzRestMethod`.

### Common Pattern
```powershell
function Get-AzXxx {
    param($ResourceId, $ApiVersion, ...)
    $uri = "$ResourceId?api-version=$ApiVersion"
    $response = Invoke-AzRestMethod -Method GET -Uri $uri
    if ($response.StatusCode -lt 200 -or $response.StatusCode -gt 299) {
        Write-Error "..."
        return $null
    }
    return $response.Content | ConvertFrom-Json -Depth 100
}
```

### Functions

| Function | HTTP Method | Resource |
|----------|-------------|---------|
| `Get-AzManagementGroupRestMethod` | GET | Management groups (with `-Recurse` option) |
| `Get-AzPolicyAssignmentRestMethod` | GET | Single policy assignment |
| `Get-AzPolicyExemptionsRestMethod` | GET (list) | Policy exemptions at a scope |
| `Get-AzResourceListRestMethod` | GET (list) | All resources in a subscription |
| `Get-AzRoleAssignmentsRestMethod` | GET (list) | Role assignments at a scope |
| `Get-AzRoleDefinitionsRestMethod` | GET (list) | Role definitions (atScopeAndBelow) |
| `Remove-AzResourceByIdRestMethod` | DELETE | Any resource by full ID |
| `Remove-AzRoleAssignmentRestMethod` | DELETE | Role assignment (supports cross-tenant) |
| `Set-AzPolicyAssignmentRestMethod` | PUT | Create/update policy assignment |
| `Set-AzPolicyDefinitionRestMethod` | PUT | Create/update policy definition |
| `Set-AzPolicyExemptionRestMethod` | PUT | Create/update policy exemption |
| `Set-AzPolicySetDefinitionRestMethod` | PUT | Create/update policy set definition |
| `Set-AzRoleAssignmentRestMethod` | PUT | Create/update role assignment |

### Error Handling
All REST methods:
1. Check HTTP status code (200–299 = success)
2. On failure, attempt to parse the error JSON body for a meaningful message
3. Call `Add-ErrorMessage` to accumulate errors
4. Return `$null` on failure (callers check for null)
5. Special case: `Remove-AzResourceByIdRestMethod` treats `ScopeLocked` errors as warnings, not failures

### TenantId Support
`Remove-AzRoleAssignmentRestMethod` and `Set-AzRoleAssignmentRestMethod` accept an optional `TenantId` parameter for cross-tenant Lighthouse scenarios, passed through to `Invoke-AzRestMethod`.
